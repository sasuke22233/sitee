# Приложение I. Приёмка, тест-кейсы, SLA

Ссылки: `TZ.md` FR-PLAN-01…03. Каждый тест-кейс трассируется к требованию.
Обозначения: **P0** — блокер запуска, **P1** — критично, **P2** — важно.

---

## 1. Критерии приёмки MVP (сводно)

1. Все **MUST**-требования `TZ.md` реализованы и подтверждены тест-кейсами ниже.
2. 0 уязвимостей Critical/High по итогам внешнего пентеста; Medium — с планом и сроком.
3. Производительность: P95 ленты ≤ 400 мс при 500 RPS; WS-доставка P95 ≤ 250 мс; ошибок < 0.1 %.
4. Безопасность данных: дамп БД не позволяет прочитать переписку, сток товаров, TOTP-секреты,
   приватные ключи (проверяется выгрузкой и попыткой дешифровки без KEK).
5. Ledger: 0 расхождений инвариантов за 7 суток стенда; сверка Solana diff = 0.
6. Доступность: 99.9 % за 30 суток стенда; успешное учение по отказу (kill -9 primary PG,
   обрыв crypto-core, падение RPC).
7. Документация: API (OpenAPI), runbook, гайды продавца и админа, схема БД — актуальны.

## 4. SLA и поддержка

| Показатель | Значение |
|---|---|

## 5. Регрессионные цепочки (прогон в CI на каждом PR)

1. `register → verify → 2fa(login) → 2fa(ops) → feed → shop → order → pay → deliver → confirm → review`
2. `order → dispute → escalate → arbitrate(refund_partial) → ledger check → appeal`
3. `create shop → rent(crown) → crown in feed → product → moderation → publish`
4. `deposit(SOL) → exchange(STARS→SOL) → gift purchase → shop boost → feed score`
5. `brute-force login → lock → captcha → unlock by timer` (ускоренное время)
6. `crypto-core down → fallback encrypt/decrypt roundtrip → format identical`
