# Приложение F. Экономика: аренда, звёзды, подарки, комиссии, ledger

Ссылки: `TZ.md` FR-SHOP-04…07, FR-STR-01…07, FR-EXC-01…05, FR-ORD-04, FR-REV-02.

---

## 1. Расчётные единицы

| Единица | Обозначение | Точность | Источник | Назначение |
|---|---|---|---|---|
| Solana | `SOL` | 9 знаков (lamports) | депозит/обмен | основная валюта: товары, аренда, выводы |
| Telegram Stars | `STARS` (`XTR`) | целые | покупка в Telegram / обмен | подарки, буст, аренда, мелкие товары |
| USDC (SPL) | `USDC` | 6 знаков | депозит/обмен | MAY, стабилизация цен |

**Курс:** площадка публикует котировку `SOL/STARS` (обновление раз в 60 с по оракулу цены SOL,
спред ≤ 2 %, комиссия обмена `fee_bps` по умолчанию 100 = 1 %). Все котировки — с `valid_until`
и идемпотентным исполнением по `quote_id` (клиент не может исполнить устаревший курс).

## 2. Ledger двойной записи

### 2.1 План счетов
| Тип счёта | Пример | Назначение |
|---|---|---|
| `user:<id>:<asset>` | `user:usr_1:SOL` | доступный баланс пользователя |
| `user_locked:<id>:<asset>` | — | заблокировано (вывод в обработке) |
| `escrow:<order_id>` | — | средства покупателя по заказу |
| `shop:<id>:<asset>` | — | выручка магазина (доступна к выводу) |
| `platform:fees` | — | комиссия площадки |
| `platform:rent` | — | доходы от аренды |
| `platform:custody` | — | корреспонденция с on-chain (депозиты/выводы) |
| `platform:stars_reserve` | — | резерв под обязательства в Stars |
| `gift:revenue` | — | выручка от подарков |

### 2.2 Проводки операций
| Операция | Debit | Credit |
|---|---|---|
| Депозит SOL | `platform:custody` | `user:X:SOL` |
| Вывод SOL (итог) | `user:X:SOL` | `platform:custody` |
| Вывод (заморозка до broadcast) | `user:X:SOL` | `user_locked:X:SOL` |
| Оплата заказа | `user:X:SOL` | `escrow:ORD` |
| Завершение заказа | `escrow:ORD` | `shop:S:SOL` (сумма − комиссия) и `platform:fees` (комиссия) |
| Возврат (полный) | `escrow:ORD` | `user:X:SOL` |
| Возврат (частичный) | `escrow:ORD` | `user:X:SOL` (часть) + `shop:S:SOL`/`platform:fees` (остаток) |
| Аренда | `user:X:SOL|STARS` | `platform:rent` |
| Покупка подарка | `user:X:STARS` | `gift:revenue` |
| Обмен STARS→SOL | `user:X:STARS` | `platform:stars_reserve`; и `platform:custody` → `user:X:SOL` (за вычетом `platform:fees`) |
| Реферальное вознаграждение (SHOULD) | `platform:fees` | `user:X:SOL` |

Каждая операция — один `tx_id`, набор проводок пишется в одной БД-транзакции, обязательны
`idempotency_key` и `kind`. Инварианты — `docs/architecture.md` §6.

### 2.3 Комиссии
| Источник | Ставка | Настраивается |
|---|---|---|
| Продажа товара | по тарифу аренды: Starter 7 %, Pro 5 %, Crown 3.5 %, Enterprise 2.5 % | админка (`shop_rent_plans.fee_bps`) |
| Аренда | 0 % (это и есть доход) | — |
| Обмен | 1 % (100 bps) | `settings.exchange_fee_bps` |
| Вывод | сетевая комиссия Solana (pass-through) + 0 % площадки | MAY: фикс. наценка |
| Подарки | наценка заложена в цену | админка |

## 3. Аренда магазинов (подписка)

### 3.1 Тарифы (значения по умолчанию, редактируются в админке)
| Тариф | SOL/мес | Stars/мес | Товаров | Операторов | Комиссия | Boost | Коронка | SLA поддержки |
|---|---|---|---|---|---|---|---|---|
| Starter | 5 | 500 | 20 | 0 | 7 % | 0.0 | — | бот |
| Pro | 19 | 1900 | 200 | 2 | 5 % | 0.5 | — | 24 ч |
| **Crown** | 49 | 4900 | 1000 | 5 | 3.5 % | 1.0 | ✅ | 4 ч |
| Enterprise | договорная | договорная | ∞ | ∞ | 2.5 % | 1.0 | ✅ + verified | менеджер |

Триал: 7 дней на Starter, 1 раз на аккаунт, требуется фактор `ops` и подтверждённый Telegram.

### 3.2 Жизненный цикл и автоматика
```
trial(7d) → active → expiring(T-5, T-3, T-1: уведомления) → [автопродление] → active
                                                        ↘ [нет средств] → grace(72h) → suspended
```
| Событие | Действие системы |
|---|---|
| T−5/3/1 день | push + чат-уведомление админу магазина, баннер в кабинете |
| T−24 ч (автопродление) | попытка списания; при неудаче — 3 повтора с интервалом 6 ч |
| T (конец периода) | `grace`: витрина с меткой «аренда истекает», **новые заказы запрещены**, чаты работают |
| T+72 ч | `suspended`: магазин скрыт из ленты/поиска, карточка доступна по прямой ссылке (read-only), активные заказы довождаются до конца, средства эскроу под контролем |
| Оплата в grace | мгновенное восстановление `active` без потери позиции |
| Отмена автопродления | статус `cancelled` по окончании оплаченного периода (без возврата) |
| Возврат pro-rata | только по решению супер-админа, с записью в аудит и фактором ops |

### 3.3 Коронка (визуальный премиум-маркер)
`is_crowned = plan.grants_crown AND subscription.status IN ('active','expiring') AND
rating_bayes >= 4.0 AND sanction_level = 'none' AND shop.status = 'active'`.
Вычисляется на сервере при чтении ленты и кэшируется в `mv_feed_score`; снятие — немедленное
при смене любого условия (событие `shop.crown.lost` → уведомление админа магазина).

### 3.4 churn-метрики
`rent_churn_total{plan,reason}`, `rent_mrr_sol`, `rent_renewal_rate`, `grace_recovery_rate`,
`trial_conversion`. Дашборд в админке.

## 4. Звёзды (Telegram Stars / XTR)

### 4.1 Пополнение
1. **Покупка в Telegram** (основной путь): TMA `Telegram.WebApp.openInvoice(url)` → Bot API
   `sendInvoice(currency="XTR", prices=[…])` → вебхук `successful_payment` → зачисление
   `platform:stars_reserve → user:X:STARS` (идемпотентность по `telegram_payment_charge_id`).
2. **Обмен SOL → STARS** во внутреннем обменнике (§5).

### 4.2 Списание
Товары (если продавец принимает Stars), подарки, аренда, буст, комиссия обменника.

### 4.3 Правила
* Stars — **не выводятся** в SOL напрямую пользователю вне обменника (анти-отмывочное правило);
  вывод в фиат — через Telegram (вне платформы).
* Возврат по спорам в Stars — на баланс Stars; при смешанной оплате возврат пропорционален.
* Refund Telegram Stars возможен только через Bot API `refundStarPayment` (срок 21 день) —
  используется для ошибочных платежей и по решению арбитра.

## 5. Обменник (Exchange)

```
GET /exchange/quote?from=STARS&to=SOL&amount=1000
  rate = oracle_rate * (1 − spread/2) * (1 − fee_bps/10000)
  to_amount = amount * rate, округление вниз до точности актива
POST /exchange {quote_id} → атомарные проводки, статус filled
```
Ограничения: мин/макс суммы (100…100 000 STARS, 0.1…1000 SOL), суточный лимит пользователя,
фактор `ops` для сумм ≥ порога, блокировка при рассинхроне ledger или отклонении оракула > 5 %
(алерт, ручной режим).

## 6. Подарки (цифровые)

### 6.1 Модель
Подарок — цифровой объект каталога площадки (не товар магазина): медиа (статика/видео/Lottie/стикер),
редкость, цена в Stars и/или SOL, эффекты:
* `boosts_shop` — временный `gift_boost` в скоринге ленты (значение и срок в карточке подарка);
* `collectible` — учёт в инвентаре с номером выпуска (без эмиссии в блокчейн на MVP);
* `rating_effect` — MAY: небольшой вклад в «лояльность» магазина (не в байесовский рейтинг,
  чтобы не допустить платную накрутку оценок).

### 6.2 Редкость и цены (рекомендуемая сетка)
| Редкость | Доля каталога | Stars | SOL | Типичный эффект |
|---|---|---|---|---|
| common | 50 % | 50–200 | 0.2–1 | стикер, бейдж |
| rare | 30 % | 200–700 | 1–3 | boost 0.15 / 3 дня |
| epic | 15 % | 700–2000 | 3–10 | boost 0.35 / 7 дней |
| legendary | 5 % | 2000–10000 | 10–50 | boost 0.6 / 14 дней + витрина в профиле |

### 6.3 Покупка и дарение
1. Выбор подарка → получатель (`self` | `user` | `shop`) → способ оплаты (Stars/SOL);
2. Порог фактора `ops`: ≥ 1000 Stars или ≥ 5 SOL;
3. Проводки: `user → gift:revenue`; при `boosts_shop` — запись `gift_boost` и `gift_boost_until`
   в `shops`, событие `shop.boosted`;
4. Карточка-подарок появляется в чате с получателем (или в канале магазина при публичном дарении),
   в инвентаре отправителя и получателя;
5. Возврат подарка невозможен (кроме технической ошибки — по решению админа).

### 6.4 Админка подарков (FR-STR-04)
CRUD + медиа-библиотека + CSV-импорт + планировщик (start/stop) + предпросмотр карточки +
статистика продаж + история изменений (diff в аудит). Обязательные поля: `sku`, `title_ru`,
`rarity`, хотя бы одна цена (Stars или SOL), `status`.

## 7. Рейтинги и бусты (анти-накрутка)

```
rating_bayes = (C*m + Σratings) / (C + n),  C = 10, m = 3.8
feed_score   = 0.30*norm(rating_bayes) + 0.20*norm(log10(sales+1)) + 0.15*recency
             + 0.15*rent_tier_boost + 0.10*geo_boost + 0.05*response_speed
             + 0.05*gift_boost − 0.20*complaint_penalty − 0.30*dispute_loss_penalty
```
* `gift_boost` ограничен 0.6 и действует ≤ 14 дней (нельзя «купить» постоянный топ);
* платные слоты продвижения — отдельная очередь `promoted`, ≤ 1 на 8 карточек, с маркировкой;
* `dispute_loss_penalty` начисляется за проигранные споры (решение арбитра), снимается через 90 дней;
* накрутка отзывов ⇒ обнуление `rating_sum/count` и санкция (§FR-SHOP-08).
