# tools/preview — живое предпросмотр-зеркало API

Песочница, в которой делается проект, не имеет тулчейнов Go и Rust (установить
их неоткуда: `go.dev/dl`, `static.rust-lang.org`, `codeload.github.com`-ассеты
заблокированы). Чтобы UI из ТЗ было видно и его можно было потрогать, API
реализовано второй раз на Node — **с тем же контрактом и теми же форматами
данных**, что и Go-бэкенд. Это зеркало, а не отдельный продукт: 104 маршрута,
та же схема ошибок, тот же WS-протокол, та же криптография.

```
npm start                 # супервизор: держит сервер живым, healthz-пинг раз в 30 с
node server.mjs           # только сервер (0.0.0.0:8080)
node smoke.mjs            # 96 сквозных проверок API + WS
node ws-client.mjs        # WS-клиент: диалоги, заказы, споры в реальном времени
```

## Что внутри

| Файл | Роль |
|---|---|
| `supervisor.mjs` | перезапускает сервер при падении (за 1 с), пишет лог, держит превью живым |
| `server.mjs` | роутер, middleware (auth, rate-limit, логи, no-cache, gzip/ETag) |
| `crypto.mjs` | AES-256-GCM конверты, HKDF, PBKDF2, TOTP, base58 — **байт-в-байт как Rust/Go** |
| `ws.mjs` | WS-хаб: `{v:1,t,ts,d}`, коды закрытия 4401/4403/4408/4429/4503 |
| `data.mjs` | демо-данные (магазины, товары, пользователи, чаты) + `demoCredentials` |
| `domain.mjs` | доменные функции: заказы, аренда, споры, звёзды, подарки, лента |
| `lib.mjs` | общее: ошибки, рейтинги, feed_score, антифрод-скоринг, системные сообщения |
| `persist.mjs` | снапшот состояния в `data/` (по умолчанию выключен) |
| `routes-*.mjs` | маршруты по областям: auth, catalog, orders, messenger, economy, disputes, admin |
| `smoke.mjs` | 96 проверок: регистрация, двойной 2FA, магазины, заказы, эскроу, споры, WS, анти-брутфорс |

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SITEED_PORT` | `8080` | порт |
| `SITEED_KEK_HEX` | генерируется при старте | мастер-ключ шифрования (64 hex). **Если не задан, ключи меняются каждый boot — демо-данные из снапшота не расшифровать** |
| `SITEED_SNAPSHOT` | `1` | грузить `data/preview-snapshot.json` при старте |
| `SITEED_RATE_SCALE` | `1` | множитель лимитов (в тестах — 6, чтобы не ловить 429) |
| `SITEED_FRONTEND_DIR` | `../../frontend` | откуда раздавать TMA |
| `SITEED_PERSIST` | `0` | писать снапшот состояния в `data/` |

## Проверка

```bash
node smoke.mjs                     # → «Итог: 96 passed, 0 failed»
node ../fe-test/run.mjs            # → «экранов 34, проблемных 0»
```

Оба набора зелёные. Демо-доступы (пароли + резервные коды 2FA) отдаёт
`GET /api/v1/dev/credentials` — они случайны на каждый boot, поэтому в тестах
их не хардкодят. Сброс антифрод-счётчиков после серии неудач:
`POST /api/v1/dev/reset-guards`.
